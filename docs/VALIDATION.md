## Reproduce checks and remaining limits

Run `pnpm test`, `pnpm demo:e2e`, `pnpm lint`, `pnpm build` and `bash scripts/prepare-convex-build.sh` with Node.js 24, pnpm 10 and Python 3. Controller host checks need `g++`; target compilation needs Arduino CLI 1.6.0 and `bash scripts/compile-arduino.sh <evidence-dir>`. [Backend tests](../tests/backend.test.cjs), [monitoring](../tests/monitoring.test.cjs), [bridge](../tests/test_bridge.py) and [host harness](../tests/firmware/controller_test.cpp) show scope.

Managed CUA remains unavailable; the requested project headless runner provides actual published browser checks. Auth0 CLI uses its own first-party global issuer/client and its default request uses a broad wildcard audience. Default and extra-scope device attempts were denied; this does not establish the exact tenant permission/policy cause or a disabled DWMS SPA grant. Inspect authorized management/log evidence through a securely bound existing-tenant grant; do not start another blind device-code attempt.

Upgraded gateways now persist session/sequence identity and gateway observation time separately from server receipt. Exact duplicates are idempotent and do not renew freshness; conflicting, replayed/out-of-order, future, >10-second delayed and receipt-only downgrade frames are rejected after upgrade. Legacy three-number HTTP remains receipt-only before upgrade; it cannot identify duplicates or true acquisition time. Neither gateway UTC nor controller uptime establishes probe acquisition UTC; initial serial backlog, clock synchronization and sensor age require physical validation. Never replay old telemetry as fresh. Field capacity, retention, maintenance cost and treatment effectiveness remain unmeasured. Fleet approval is shared-fleet access, not per-site tenant isolation.
