## Reproduce and interpret the checks

Use Node.js 24, pnpm 10 and Python 3. Run `pnpm test`, `pnpm demo:e2e`, `pnpm lint`, `pnpm build`. CI also runs `bash scripts/prepare-convex-build.sh` in isolation. Controller host checks use `g++`; target compilation uses `bash scripts/compile-arduino.sh <evidence-dir>`. Browser checks use optional existing Python Playwright/Chromium, not an application dependency: `python3 scripts/verify-public-demo.py --url <published-origin> --output-dir <evidence-dir>`. Recovery-fixture checks require a local Vite origin and never authenticate or call production.

Gateway observation UTC, server receipt, sequence/session identity and controller uptime remain distinct. Exact duplicates do not renew freshness; replay/out-of-order, conflicting, future, delayed and receipt-only downgrade frames are rejected after protocol upgrade. Legacy three-number HTTP is receipt-only before upgrade and cannot establish acquisition time or duplicate identity. Gateway time does not prove probe acquisition UTC. Clock synchronization, initial serial backlog, sensor accuracy and relay effectiveness still require physical validation. Never replay stale telemetry as fresh or replace failed probes with demo values.

Device OFF requests and software ACKs do not prove physical shutdown. AI cannot issue actuator commands or override deterministic safety. The monitored parameters alone do not establish drinking-water safety or regulatory compliance. Field capacity, treatment effectiveness, costs and savings remain unmeasured.
