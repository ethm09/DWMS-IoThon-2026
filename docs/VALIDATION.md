## Prioritized acceptance checklist

- [x] **P0 — Public intelligence:** genuine guest AI, Arabic/English interaction, context/citations, cooldown/draft recovery, mobile access and quota isolation verified. Failed provider calls never generate substitute replies.
- [x] **P0 — Monitoring and safety:** all five scenarios and deterministic emergency/recovery logic preserved; AI has no actuator, interlock or automatic-restart authority.
- [x] **P0 — Verification:** 88 Node +20 Python tests, 11 isolated backend checkpoints, seven production anonymous denials, lint/build/typecheck, host harness, Uno compilation and application CI passed.
- [x] **P0 — Published evidence:** five-width scenario run, genuine desktop/mobile conversations, fresh v13 captures and PDF/CSV downloads recorded. No operational mutations or browser runtime errors observed in those runs.
- [ ] **P0 — Secure session:** provide a functioning secure browser handoff and sign in to an existing approved DWMS account. Verify registration, logout/reload, rejected/unapproved users, roles, private histories, subscriptions and device workflows. Do not send passwords/tokens through chat. Existing accepted public configuration is in [SETUP.md](SETUP.md#auth0-application-settings-and-authorization-blocker); no duplicate callback or new service is needed.
- [ ] **P0 — Authenticated Ethm:** verify genuine read-only conversation grounded in authorized device/history/alerts, offline/insufficient-data behavior, persistence/privacy and desktop/mobile interaction.
- [ ] **P0 — Enable Live:** only after real-session gates pass, publish with `VITE_DWMS_LIVE_ENABLED=true` and repeat acceptance. Current `/live` is a readiness gate, not an accepted operational session.
- [ ] **P1 — Physical commissioning:** recover the prototype; preserve firmware/wiring, identify/calibrate probes, validate qualified isolated relay/load safety and record a physical end-to-end trace.
- [ ] **P2 — Predictive claims:** validate statistical assumptions and uncertainty on adequate independent physical data before promoting anticipation or accuracy.

## Reproduce and interpret the evidence

Use Node.js 24, pnpm 10 and Python 3. Run `pnpm test`, `pnpm demo:e2e`, `pnpm lint`, `pnpm build`. CI generates Convex bindings in isolation. Host checks use `g++`; target compilation uses `bash scripts/compile-arduino.sh <evidence-dir>`. Optional Python Playwright/Chromium checks are not an application dependency: `python3 scripts/verify-public-demo.py --url <published-origin> --output-dir <evidence-dir>`. This runner does not submit model questions; genuine AI checks consume the finite shared allowance and should not be repeated without need.

The guest budget record at 2026-11-28T01:59:19Z shows **91,166 reserved tokens /250,000**, seven model attempts and 20 sessions. Reservations are conservative allowance consumption, not an invoice or actual token-usage measurement. Failed/ambiguous calls are not refunded. The non-recurring cap, limits and reviewed tariff basis are in [SETUP.md](SETUP.md#guest-ethm-isolation-and-finite-allowance); it is not a Convex/hosting cost cap. No new purchase, subscription or automatic recharge was enabled. [Budget record](screenshots/budget-check.json).

Genuine QA first exposed missing canonical units and then a valid cooldown that lost a failed draft. Explicit units, relevant citations, server cooldown metadata and preserved drafts were fixed before the recorded final conversations. AI output remains interpretation requiring operator review. Report dates distinguish requested and loaded evidence, not complete daily/weekly coverage.

Gateway observation UTC, receipt, sequence/session identity and controller uptime remain distinct. Exact duplicates do not renew freshness; replay/out-of-order, conflicting, future, delayed and receipt-only downgrade frames are rejected after protocol upgrade. Legacy three-number HTTP is receipt-only before upgrade. Gateway time does not prove probe acquisition UTC. Clock synchronization, initial serial backlog, sensor accuracy and relay effectiveness need physical validation. Never replay stale telemetry as fresh or replace failed probes with Demo values.

Device OFF requests and software ACKs do not prove physical shutdown. AI cannot issue actuator commands or override deterministic safety. These monitored parameters alone do not establish drinking-water safety or regulatory compliance. Field capacity, treatment effectiveness, costs and savings remain unmeasured.

Video production, presentation revisions and competition submission remain paused. Existing media/deliverables and the [hardware package](../deliverables/DWMS-Hardware-Reconnection.zip) are preserved; prior media is historical evidence, not this Ethm release. PR #2 remains a draft and unmerged; no competition application was submitted.
